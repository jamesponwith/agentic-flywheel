# Retro — August 2026

The first application of ADR 0001's cost test. That it is the first is itself
the headline: the test was written on 2026-08-15 to replace a category ban with
a budget, and then never run, which meant every subsequent decision to build
something was made with no mechanism saying no.

## What got better, and why

Three things, all cheap, all verifiable by running them: the Build gate now
rejects in five repos (it had never run once); CI gates every PR at ~30s; the
release pipeline ships four signed platform binaries in 59s. None of these
needed the fleet. All three were repairs, not new construction.

The detection layer also got sharper — the review panel caught a reviewer that
printed its recording step instead of running it, and an unattended agent found
a git-environment bug that had been silently rewriting the repo its own tests
ran in. That is real, and it is the strongest argument for the loop existing.

## What is over budget

ADR 0001 says a stage over its declared cost for two consecutive retros gets
deleted or automated. Nothing has ever declared a cost, so this retro declares
them, and applies the test once. Where the answer is already obvious the test
is applied immediately rather than waiting a second cycle — a mechanism with
**zero call sites** cannot improve next month.

## The uncomfortable one

**17 direct-to-main commits in this repo against a budget of 2.** The rule's
prescribed answer is delete the gate or automate it. The gate is good, so:
automate it. Branch protection on `main` in all five repos would make the rule
self-enforcing, and would also close the D3 finding that `git push origin main`
is merge authority for an agent without touching any denied command.

I am the one who bypassed it 17 times, which is exactly the case the rule was
written for.

## Is the flywheel paying for itself?

Partly, and not where the effort went. The cheap half — gate, CI, release,
templates, beads, ADRs — costs almost nothing and demonstrably works. The
expensive half — the coordinator, roles, message contract, reservations, merge
slot, cost accounting, agent metrics — consumed most of the build and has
produced **one merged PR and zero unattended nights.**

That is not an argument to delete the coordinator. It is an argument that it is
unfinished, and that four mechanisms around it were built before the thing they
support had ever run once. ADR 0001 existed to prevent precisely that and was
never consulted.

## Applied today

- Roster cut from 8 agents across 5 roles to 2 builders. `Roster.Match` had one
  call site and only ever matched `role=builder`.
- ADR 0007 marked **aspirational, unimplemented**. Kept rather than deleted
  because the reasoning is what I would want when a second role exists; deleted
  next retro if still at zero implementation.

## Proposed, not created — the human picks

The skill's rule: proposing ten and having two accepted is a good month;
creating ten unasked is how a board becomes noise.

1. **Branch-protect `main` in all five repos.** (P0) The prescribed answer to
   17 bypasses of a good gate, and it also closes the finding that
   `git push origin main` is merge authority for an agent without touching a
   denied command. Needs a human: it changes how you work, not just the code.
2. **Wire the runner to record `usd`/`tokens`, or delete `fleet cost`.** (P1)
   Zero measurements in 22 log lines. It is the instrument this test depends
   on; unmeasured next retro means the cost test stays undecidable.
3. **Run one unattended night, or stop calling it a fleet.** (P1) `nightly.sh
   install` is one command and has never been run.
4. **Delete the agent-metrics dashboard panel** until at least two of four
   metrics measure something. (P2)
5. **Decide whether territory reservations are load-bearing.** (P2) The drill
   proves the property; nothing in the loop enforces it, because no
   `PreToolUse` hook exists. Either add the hook or stop claiming the property.
6. **Re-measure bootstrap time.** (P2) The published 2m55s predates all of v2.

## Next retro

The test is only meaningful applied twice. Whatever survives today gets measured
again in September, and anything still at zero call sites or zero measurements
is deleted without further argument.
